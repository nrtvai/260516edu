AI를 잘 쓰는 핵심은 질문이 아니라, 상황을 다 털어놓는 겁니다.

결론부터 갑니다. 채팅창에 한 줄씩 예쁘게 질문하는 건 AI 서비스의 1%만 쓰는 방식입니다. 마이크로 맥락을 쏟아내고, 기준을 만들고, 에이전트에게 실행시켜야 업무가 실제로 줄어듭니다.

오늘의 전환

채팅 AI 1%
프롬프트 기준화 10%
에이전트·자동화 90%

오늘 목표: 멋진 AI 지식이 아니라, 내 업무 하나를 에이전트 업무로 바꾸는 관점.

01

솔루션: 마이크 켜고 주절주절 말하세요.

현재 상황, 원하는 것, 결과물 형태, 제한조건, 내가 아는 것, 모르는 것, 용도, 계기, 나의 정체와 목적을 최대한 끄집어낸 뒤 마지막에 이렇게 말합니다.

“이걸 바탕으로 내가 바로 쓸 수 있는 프롬프트를 써줘.”

마이크 모드 대본

지금부터 내가 상황을 두서없이 말할게.
내가 말한 내용을 바탕으로 좋은 프롬프트를 만들어줘.

프롬프트에는 다음을 반드시 포함해줘:
- 현재 상황
- 원하는 결과
- 결과물의 형태
- 제한조건
- 내가 아는 것과 모르는 것
- 이 결과물을 쓰는 용도
- 내가 이걸 하게 된 계기
- 내 정체성과 목적

부족한 정보가 있으면 먼저 질문해줘.
02

요약, 조사, 글쓰기는 “기준”을 먼저 먹이면 달라집니다.

좋은 모델은 이미 “잘 요약된 자료”와 “잘 정리된 문서”의 기준을 엄청나게 봤습니다. 그래도 사람마다 취향이 갈립니다. 그래서 매번 기준을 잡아주거나, 내 기준 프롬프트를 저장해야 합니다.

요약 / 정리

파일을 던져도 되지만 기준을 같이 던져라

“짧게 요약” 대신 “의사결정용으로, 쟁점·결론·확인사항을 나눠서”라고 요청합니다.

자료 조사

Deep Research + Perplexity + Grok/X

사실확인은 리서치 도구, 출처 비교는 Perplexity, 민심과 실시간 반응은 Grok/X로 봅니다.

문서 작성

잘 쓴 문서를 많이 먹여라

보고서, 메일, 제안서 샘플을 주고 “이 기준에 맞춰 써라”라고 해야 말맛과 구조가 맞습니다.

03

자동화는 채팅이 아니라 코딩 에이전트에서 시작됩니다.

개발 에이전트는 개발자 전용 장난감이 아닙니다. 목표에 가까워지기 위해 코드를 쓰고, 도구를 실행하고, 파일을 만들고, 검증까지 하는 실행형 직원에 가깝습니다.

채팅 답변을 받는다
코덱스 / 클로드 코드 파일을 만들고 실행한다
루틴 / 자동화 반복 업무를 맡긴다
04

비개발자용 단어 설명은 네 개면 충분합니다.

LLM

말과 자료의 패턴을 이해하고 다음에 올 답을 만들어내는 거대한 언어 모델.

모델

GPT‑5.5, Claude Opus 4.7, Gemini 3.1 Pro처럼 실제로 생각하고 답하는 엔진.

API

앱, 문서, 업무 시스템이 모델을 불러다 쓰게 해주는 연결 통로.

에이전트

목표를 받고, 도구를 쓰고, 실행하고, 중간 결과를 확인하며 계속 움직이는 AI 작업자.

05

서비스 비교는 공식 사실과 사용감을 분리해서 보세요.

2026-05-16 기준. 아래 평가는 강한 주관 그대로입니다. 싸우자는 게 아니라 빨리 고르자는 겁니다.

도구 공식 사실 현장 사용감
ChatGPT / GPT‑5.5 ChatGPT와 Codex에서 사용 가능. 코딩, 리서치, 데이터, 문서 작업에 강함. 만능. 비싸지만 돈값 함. 이미지와 음성 대화도 현재 제일 무난하게 좋음.
Claude / Opus 4.7 코딩, 에이전트, 긴 작업, 고해상도 이미지 이해를 강화한 모델. 비싼데 자주 답답함. 그래도 개발할 때 개떡같이 말해도 알아듣는 편이라 많이 씀.
Gemini / 3.1 Pro Google의 고급 멀티모달 추론 모델. Workspace와 결합이 강함. 글을 잘 쓰고 말맛이 좋음. Google Workspace 쓰면 추가 지출 없이 시작하기 좋음.
06

채팅으로만 쓰면 여기서 막힙니다.

채팅은 답변을 줍니다. 에이전트는 파일을 만들고, 실행하고, 실패하면 고치고, 다시 확인합니다.

채팅 AI의 한계

  • 결과를 직접 파일로 정리하지 않음
  • 반복작업을 스스로 실행하지 않음
  • 검증과 수정 루프를 사람이 계속 밀어야 함

Codex / Claude Code가 여는 것

  • 자료를 읽고 결과 파일을 생성
  • 웹페이지, 스크립트, 자동화 도구를 직접 작성
  • 테스트하고 실패를 고치며 목표에 접근
07

설문 답변 중 실제로 에이전트화할 수 있는 것들

기안, 비교견적, 보고서, 시장조사, 데이터 정리, 엑셀 서식, 영어 메일 후속조치. 전부 “반복 가능한 업무 단위”로 바꿀 수 있습니다.

에이전트에게 줄 업무

업무를 입력하면 여기에 에이전트용 작업 지시가 만들어집니다.
08

기업용 계정이어도, 미숙한 사용은 위험합니다.

팀/엔터프라이즈 요금제는 개인 무료 계정보다 안전한 편입니다. 그래도 전체공개 링크, 고객정보 업로드, 서비스 파일 삭제 같은 사고는 사용자가 만들 수 있습니다.

개인정보와 고객정보는 기본적으로 넣지 않는다
공유 링크는 공개 범위를 확인한다
자동화는 삭제 권한부터 막고 시작한다
중요 문서는 사람 검토를 마지막 단계로 둔다

모바일 핸드아웃

프롬프트는 쓰는 게 아니라 채굴하는 것

마이크를 켜고 상황을 다 말한 뒤 “이걸 바탕으로 프롬프트를 써줘”라고 요청합니다.

도구 선택 감각

만능과 이미지와 코딩은 ChatGPT, 업무 연동과 개발 루프는 Claude, Workspace와 글맛은 Gemini.

네 단어

LLM은 엔진, 모델은 제품별 두뇌, API는 연결 통로, 에이전트는 실행하는 작업자.

업무 자동화의 시작

“답변해줘”가 아니라 “파일을 만들고 실행하고 확인해줘”라고 말하는 순간부터 다릅니다.
